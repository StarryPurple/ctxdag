# 测量结果

## 实验环境

正式运行使用 RTX 4090、vLLM 0.10.1 与 Qwen2.5-14B-Instruct-AWQ。原始报告遵循 `contextdag.measurement.v1`，保存在 `bench/results/`。运行对应 commit `daaa346`，报告标记为 dirty，因为测量实现本身尚未提交；因此结论必须与当前工作树一起复现。

## LongBench

从 `multi_news_e`、`2wikimqa_e`、`hotpotqa_e`、`triviaqa_e` 和 `qasper_e` 各取 20 条，共 100 个样本。四个条件使用同一模型与 8,000 token 输入预算。下表以 `full` 为基准；置信区间是固定种子、10,000 次按样本配对 bootstrap 的均值得分差 95% 区间。

| 条件 | 均分 | 输入 token | 相对 token | 得分差（95% CI） |
|---|---:|---:|---:|---:|
| full | 0.2763 | 402,969 | — | — |
| protocol | 0.2858 | 415,498 | +3.1% | +0.0095（-0.0270, +0.0448） |
| pruned | 0.2875 | 157,870 | -60.8% | +0.0112（-0.0368, +0.0607） |
| no-headers | 0.2630 | 402,127 | -0.2% | -0.0133（-0.0528, +0.0225） |

`protocol` 的目录和边界标记产生净开销；固定保留前半段的 `pruned` 明显减少 token。三个得分差区间均跨零，当前样本不能证明质量提升或无损。分数据集每组仅 20 条，也没有稳定的方向一致性。因此该结果支持扩大选择性裁剪实验，不支持直接宣称协议本身节省 token。

## tau-bench

retail 环境取 10 条任务，oracle 成功率为 100%，说明任务与判分管线可用；baseline 和 protocol 在该次生成中均为 0%。两者平均步数分别为 3.8 和 3.2，总输入 token 分别为 87,684 和 66,860，但步数不同，不能据此比较效率。

前三条任务的诊断复跑得到 baseline 0/3、protocol 1/3。成功轨迹包含查询订单、查询商品、执行换货和回复，表明工具链能够完成任务；正式运行的零成功率更符合小样本与生成非确定性，而非固定适配器故障。下一轮必须固定采样参数、增加任务数和重复种子，并按失败类型记录错误，才可比较任务质量。

## vLLM 前缀缓存

每个条件均在独立冷启动服务中运行，且首轮 cached token 为零，避免跨条件污染。

| 场景 | baseline 命中率 | protocol 命中率 | baseline / protocol 总延迟（秒） |
|---|---:|---:|---:|
| refund_policy | 18.6% | 25.3% | 0.452 / 0.562 |
| sequential_chat | 34.4% | 55.4% | 0.599 / 0.563 |
| shared_knowledge | 33.6% | 38.6% | 2.415 / 2.122 |

三种场景的前缀命中率都提高，但短场景延迟反而增加，样本量也很小。这只证明当前渲染可改善 vLLM 的共享前缀复用，不证明任意 DAG 节点或非前缀 KV 可复用。

## 选择—恢复冒烟

使用同一 14B 模型，从五个数据集各取 1 条验证闭环。关键词初选在 5 条中有 3 条发出合法 `require`；三次请求均获授权、加载一个节点并完成恢复，最终得分全部高于初始得分。总体均分由 0.0870 升至 0.3132。恢复条件累计输入 20,708 token，比 full 的 21,804 少 5.0%；初选本身为 5,158 token。

该结果只证明模型能够使用目录完成受限缺页恢复。样本量不足以估计质量或净 token 收益；恢复累计成本也表明，下一轮必须同时优化初选召回率和恢复提示长度。

## 选择—恢复参数扫描

固定 seed 0，从五个数据集各取 10 条。下表 token 为应用实际发送的逻辑输入总量；得分差和 95% 配对 bootstrap 区间均以 full 为基准。

| 条件 | 最终均分 | 相对 full 得分差（95% CI） | 逻辑 token | 相对 full |
|---|---:|---:|---:|---:|
| full | 0.2755 | — | 200,511 | — |
| protocol-full | 0.2343 | -0.0412（-0.1045, 0.0104） | 206,777 | +3.1% |
| fixed-half | 0.2697 | -0.0059（-0.0910, 0.0786） | 78,222 | -61.0% |
| keyword 25% / 初选 | 0.0978 | -0.1777（-0.2570, -0.0975） | 47,081 | -76.5% |
| keyword 25% / 1 轮 | 0.2311 | -0.0445（-0.1006, 0.0032） | 165,450 | -17.5% |
| keyword 25% / 2 轮 | 0.2285 | -0.0471（-0.1167, 0.0172） | 194,299 | -3.1% |
| keyword 50% / 1 轮 | 0.2802 | +0.0047（-0.0370, 0.0565） | 197,330 | -1.6% |
| keyword 50% / 2 轮 | 0.2625 | -0.0130（-0.0811, 0.0499） | 196,879 | -1.8% |
| keyword 75% / 1 轮 | 0.2442 | -0.0314（-0.1165, 0.0517） | 196,904 | -1.8% |
| keyword 75% / 2 轮 | 0.2249 | -0.0507（-0.1314, 0.0304） | 216,210 | +7.8% |

所有预算下，恢复相对只初选均有显著正增益：一轮恢复分别提高 0.1333、0.2019 和 0.1717，配对区间均高于零。第二轮没有提高总体点估计，且在 25% 和 75% 条件中增加明显 token，因此当前默认应限制为一轮。25% / 一轮保留 17.5% 净 token 节省，但点估计质量低于 full；50% / 一轮质量最接近 full，但逻辑 token 优势仅 1.6%。

API 用量与 cached token 已逐调用记录。扫描在同一热服务中顺序执行，缓存数据受运行顺序影响，只能用于诊断；不能与独立冷启动缓存实验合并为因果结论。恢复调用确实出现前缀命中，但命中不足以抵消重复发送完整上下文的逻辑成本。


## 摘要与全文检索对照

固定一轮恢复和 seed 0，从五个数据集各取 20 条。全文只用于 BM25 索引，模型看到的目录摘要、协议和 token 预算与摘要检索相同。

| 索引与预算 | 初始均分 | 恢复后均分 | 相对 full 得分差（95% CI） | 逻辑 token | 相对 full |
|---|---:|---:|---:|---:|---:|
| full | 0.2686 | 0.2686 | — | 402,969 | — |
| summary 25% | 0.0835 | 0.2037 | -0.0649（-0.1170, -0.0156） | 341,900 | -15.2% |
| fulltext 25% | 0.1231 | 0.2398 | -0.0287（-0.0818, 0.0239） | 332,551 | -17.5% |
| summary 50% | 0.1157 | 0.2600 | -0.0086（-0.0475, 0.0294） | 371,789 | -7.7% |
| fulltext 50% | 0.0979 | 0.2388 | -0.0298（-0.0877, 0.0250） | 365,472 | -9.3% |

25% 预算下全文相对摘要的点估计为 +0.0361，50% 下为 -0.0212；两个配对区间都跨零。全文索引没有形成稳定优势，说明简单 BM25 同时获得更多证据词和更多噪声。摘要 50% 是本轮最稳健点：质量差异区间跨零并保留 7.7% 逻辑 token 节省。全文 25% 节省 17.5%，但质量不确定性更大。

恢复触发率为 62%–73%，新增节点内容仍是主要成本。缓存与延迟来自同一热服务的顺序运行，只作诊断；不能据此声称全文或摘要索引改善底层计算。


## 稳定前缀恢复传输

固定 seed 0、摘要检索 50% 预算和最多一轮恢复，从五个数据集各取 10 条。`messages` 保持初始 user 消息逐字不变，只追加 assistant 的 `require`、新加载节点、原问题和回答指令；`flattened` 在恢复轮重渲染完整闭包。两组分别冷启动开启 prefix caching 与逐请求 token 明细的 vLLM。50 条中有 35 条触发恢复，且两种传输的初始输出和触发集合完全相同。

| 传输 | 最终均分 | 二次调用 API token | 二次调用 cached token | 二次命中率 | 二次平均延迟 |
|---|---:|---:|---:|---:|---:|
| `flattened` | 0.3081 | 143,127 | 24,288 | 16.97% | 6.57 秒 |
| `messages` | 0.2542 | 148,437 | 33,440 | 22.53% | 7.00 秒 |

稳定前缀使二次调用 cached token 增加 37.7%，命中率提高 5.56 个百分点；未缓存输入从 118,839 降至 114,997（-3.2%）。平均延迟差为 +0.43 秒，配对 bootstrap 95% 区间为 -0.84 至 +1.75 秒，不能证明延迟改善。

质量差为 -0.0539，配对 bootstrap 95% 区间为 -0.1064 至 -0.0150，不能视为语义等价。重新在追加消息末尾提供原问题只能部分修复下降；2WikiMQA 和 Qasper 的下降最明显。结果证明当前多消息传输提高了真实前缀复用，同时说明模型对多轮恢复和单轮闭包重渲染的响应分布不同。协议层需要先解决恢复后的回答约束，再判断缓存收益能否转化为端到端收益。

## 原生工具显式路由

固定 seed 0，在 `2wikimqa_e` 前 50 条上使用 Qwen2.5-14B-Instruct-AWQ、摘要检索 50% 与最多一轮恢复。模型每轮必须在 `require_context` 和 `return_answer` 中选择；参数 schema 仅允许当前目录中的 node id。50 条中 15 条（30%）加载了一个已授权节点，10 条加载后得分提高，1 条在加载后的最终控制响应未通过解析。均分由 0.1090 升至 0.1422，配对 bootstrap 95% 区间为 +0.0143 至 +0.0561。

这证明原生工具可以将“是否补充上下文”变成模型的显式、受授权决策，并在该受限切片带来可测质量增益；它不证明端到端效率提升。15 次恢复额外发送 71,708 个逻辑输入 token，恢复调用平均延迟 8.23 秒。所有调用累计报告 45,632/165,181 cached/API prompt token，但服务处于热态，不能把该数值解释为独立缓存因果效应。后续报告会保留工具解析失败原因；下一轮应在同样的冷启动设计下与等语义的非工具基线配对，分别测质量、逻辑 token、真实 cached token 与延迟。

## 原生工具冷启动对照

固定 Qwen2.5-14B-Instruct-AWQ、2wikimqa_e 前 20 条、摘要检索 50% 与最多一轮恢复；每个条件在独立冷启动的 vLLM 服务中运行。native 条件使用严格证据门槛：只有可见全文已显式包含全部所需事实时才可 `return_answer`。

| 条件 | 最终均分 | 加载数 | 恢复轮 cached/API token | 逻辑 token | 总延迟 |
|---|---:|---:|---:|---:|---:|
| 初选不恢复 | 0.0447 | 0/20 | — | 29,240 | 65.0 秒 |
| 文本标签恢复 | 0.3185 | 17/20 | 22,032/87,614（25.2%） | 116,361 | 136.0 秒 |
| native tool（稳定 schema） | 0.1932 | 19/20 | 33,200/105,734（31.4%） | 128,875 | 248.1 秒 |

初始的动态 tools enum 在加载后改变 chat template，native 恢复轮命中率只有约 2.9%。将 schema 固定为初始授权目录后，命中率升至 31.4%，同时运行时继续验证实际 `require` 授权；这提供了真实 vLLM 前缀缓存收益的证据。tool result 追加了“已加载、最后一轮应作答”的状态，避免因静态 enum 重复请求已加载节点。

native 的点估计质量仍低于标签，差为 -0.1252，但 20 条配对 bootstrap 95% 区间为 -0.2776 至 +0.0179，尚不足以断言差异。native 仍出现 1 次无效工具响应，且总延迟更高。当前可确认缓存传输层可用，不能确认 native 路由已达到标签路径的任务质量或效率。

## 决策

恢复机制、稳定 tools schema 与 tool-result 状态反馈均已获得真实引擎测量支持；它们不等于节点级 KV 复用，也未使 native 路由达到稳定的任务质量或延迟收益。下一步保持摘要 50% 与最多一轮恢复，扩大独立冷启动样本，并将模型特征索引与启发式/全文检索作配对召回和任务质量比较。只有质量容忍区间、逻辑 token 与真实缓存收益共同稳定后，才进入节点/段粒度 KV 原型。
