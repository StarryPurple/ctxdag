# ContextDAG Context Compiler

## 研究命题

ContextDAG Context Compiler 位于 Agent 运行时和推理引擎之间。它把带内容身份、依赖、版本和授权范围的上下文 DAG 编译为引擎可执行的请求计划，使语义上共享的证据闭包转化为可复用前缀、稳定控制面和可路由缓存描述符。

目标不是改善任意单次 RAG 的检索质量，也不是替代引擎的 KV 合并、分层存储或负载均衡。目标是在相同模型、相同授权边界和可接受质量损失下，减少 Agent 工作流的真实重复 prefill。

## 编译契约

输入是不可变节点 DAG、请求目标、当前 Agent 状态、候选目录、预算和授权策略。编译器输出：

1. 上下文布局：规范拓扑序的共享证据块、可替代摘要块与请求特有后缀；
2. 控制面：固定 grammar 的 `require_context` / `return_answer` 接口，运行时解析节点身份并校验授权；
3. 缓存描述符：由渲染版本、节点内容 id、布局边界和模型模板版本组成的可比较 key；
4. 调度提示：可传给 serving router 的共享闭包指纹与预期复用量。

编译不得改变节点正文或伪造节点依赖；实际加载节点、闭包和拒绝原因必须记录。固定控制 grammar 不意味着固定授权：每个动作仍由当前目录和策略在运行时验证。

## 与引擎的分工

vLLM/SGLang 负责 token 级前缀命中、KV 存储、批处理和执行。编译器在调用前决定哪些语义对象成为共享前缀、哪些状态必须追加，以及两个请求是否可声明为同一共享闭包。引擎仍只看到普通消息与工具调用，不需理解 DAG。

基线包括完整历史、平铺标签/目录、动态工具 schema、固定 grammar 工具、普通 prefix-aware routing，以及可用的非前缀 KV 方案。逻辑 token 或离线 Accountant 不得作为引擎收益。

## 可证伪假设

**H1：稳定控制面。** 相同语义访问策略下，固定 grammar 与运行时授权相比动态 schema 提高真实共享前缀复用，且质量不低于预先声明的容忍阈值。

**H2：依赖闭包布局。** 对共享祖先和分叉状态的 Agent 工作流，规范闭包布局比时间拼接历史产生更长可复用前缀，并降低 TTFT 与 GPU prefill token。

**H3：DAG 感知路由。** 多副本场景中，按共享闭包指纹路由在相同 SLO 下优于仅按请求负载或原始字符串前缀的路由；在低重叠或负载偏斜时必须退化为普通均衡而不恶化尾延迟。

三个假设都允许失败。H1 可由当前原型先验证；H2 要求真实工作流 trace；H3 要求多副本 serving 实现。

## 评测与实施

每个条件固定模型、采样参数、任务、上下文预算与授权策略，独立冷启动并报告置信区间。主指标是任务成功率、TTFT、端到端 P50/P95、吞吐、实际 prefill token、KV 命中/加载字节和拒绝/越权次数。每个 trace 保存 DAG、编译计划、请求序列和服务端观测，以支持重放与消融。

1. 定义 trace 格式并采集 vLLM 真实观测；
2. 用现有 tags、动态 tools 和固定 grammar tools 完成 H1；
3. 实现布局编译器和 cache descriptor，完成 H2；
4. 接入 SGLang；
5. 构造多副本负载并验证 H3；
6. 只在 H1--H3 成立后探索节点/段级 KV 优化。
