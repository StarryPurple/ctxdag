# 第 2 部分：协议设计

本部分是协议设计的完整定义：节点、标签、目录与摘要、展开与会话、约束。

## 1. 节点设计

### 1.1 节点是什么

节点是上下文的基本单元：一块**自包含**的内容。典型来源是子任务的结果、
一段思考、一次工具调用的输出。自包含的意思是：节点脱离任何上下文仍然
语义成立——这是它能在不同 Agent 之间被复用、被共享的前提。

### 1.2 节点结构

- `content`：正文（必填）
- `refs`：直接依赖的节点 id 列表（可空；空表示根节点）
- `meta`：可选元信息（如 Agent 名、任务名、时间戳、token 数）

### 1.3 节点 id（内容寻址）

- id 由 `content`、`refs`（直接依赖）、`meta` 经规范化后计算 SHA-256，取前 16 位十六进制；
  `refs` 按集合参与寻址（排序后哈希），声明顺序不影响 id；
- 内容相同 → id 必相同（不会产生重复节点）；
- 内容不同 → id 不同（修改任何输入都等于产生新节点）；
- 因此节点**不可变**：生成后不会、也无法被修改，旧节点永远保留。

### 1.4 节点边界由谁决定

基线设计：**编排层决定**。一次注册调用（`register`）产生一个节点，
边界落在事件或轮次上（一条消息、一次工具调用、一个子任务结果）。

模型自主生成节点标签属于**可选研究线**，不是基线：基线不依赖模型"会"
生成结构，只要求模型"能"读写给定格式的上下文。

### 1.5 边界来源建议（按优先级）

1. 事件/轮次边界：消息、工具调用、子任务结果——多 Agent 协作的主切分；
2. 文本结构边界：段落、标题、代码块——长文档场景；
3. 固定长度切分：仅作为对照实验，不作为默认。

### 1.6 本节不变量

- id 由内容确定，修改内容必然得到不同 id；
- 节点一旦生成不可修改；
- 直接依赖只能指向已存在的节点（注册时校验，见第 5 章约束）。

### 1.7 待决策

- 16 位十六进制（64 位）的碰撞概率在研究规模下可忽略；是否需要更长或
  全量摘要，待实际规模出现后再定。

### 1.8 示例

```python
# 注册根节点：content + 直接依赖 + meta → id
brief = session.register(
    content="客户要求：退款订单 #X（$120），并换货为型号 A。",
    refs=[],                              # 直接依赖为空 → 根节点
    meta={"agent": "orchestrator"},       # 可选元信息
)
# brief.id   → "4cd5f05386b7b6ab"（SHA-256 指纹，前 16 位十六进制）
# brief.refs → []（直接依赖为空）

# 注册依赖节点：直接依赖只写"前沿"
node1 = session.register(
    content="已核实订单：金额 $120，符合退款条件。",
    refs=[brief.id],                      # 直接依赖：仅 brief
)
# node1.refs → [brief.id]
# node1 的依赖集 = {brief, node1}：直接依赖 brief + 自身

# 内容寻址：相同输入 → 相同 id
node2 = session.register(
    content="已核实订单：金额 $120，符合退款条件。",
    refs=[brief.id],
)
# node2.id == node1.id（天然去重）
```

## 2. 标签设置

### 2.1 两种标签

- `<ref=id>` 或 `<ref=id1,id2>`：**生成之前**发出，前瞻声明——本节点只读这些节点的依赖集；
- `<require=id>`：**生成中途**发出，缺页请求——请求扩展当前依赖集并重新展开。

### 2.2 语法规则

- id 必须是 16 位十六进制字符（对应内容寻址 id）；
- `<ref>` 可引用多个节点，逗号分隔；
- 标签出现在 Agent 输出的文字中，运行时解析提取；
- 解析是确定性的：符合语法的全部提取，其余文字按正文处理。

### 2.3 语义

- `ref` 是**前瞻声明**：在内容生成前发出，运行时据此展开依赖集作为生成时的上下文；
- 引用是**传递的**：只需引用"前沿"节点，其祖先经依赖集自动带入；
- `require` 是**缺页请求兜底**：生成中途发现缺少节点时发出，运行时把该节点加入
  依赖集、重新展开后继续；代价是一次额外的处理，计入缺页请求次数；
- **require 即节点边界**：`<require=X>` 之前的内容注册为节点 A（refs = 初始声明），
  之后的内容注册为节点 B（refs = [A, X]）——需求信息最终落在 B 的 refs（最前面），
  标签本身只是边界标记，不进入任何节点内容；
- **声明顺序**：refs/requires 的顺序对 id 与渲染无影响（按集合处理），
  保留声明顺序仅供可读性与追溯。

### 2.4 谁写标签

- 基线：**编排层**写与读——依赖由框架代码决定，确定、无幻觉；
- 可选：模型自主生成——协议层支持解析，但正确性不依赖它（契约兜底），
  是否可靠由未来的测量实验回答。

### 2.5 校验与契约

- 引用不存在的 id → 拒绝该操作（报错），不静默接受；
- Grounding 约束分两条（纯代码校验，API 模型同样适用）：
  - `ref` 的 id 必须属于当前依赖集；
  - `require` 的 id 必须属于当前目录（见第 3 章）；
- 校验失败的兜底：提供全量上下文回退，或让该 Agent 重试。

### 2.6 与正文的区分

基线路径中标签由编排层写入，模型与用户只产生正文，正文中的形似标签文字
不会被解析，不存在误识别。模型自主声明路径（可选）下，误识别防护为：

1. **格式稀有性**：`<ref=` 后必须紧跟恰好 16 位十六进制再跟 `>`，自然文本
   命中概率极低；如需更强，可改用更特殊的定界符（如 `<|ref|...|>` 风格）；
2. **校验兜底**：被解析出的 id 必须已注册且满足 grounding，否则按正文处理
   或拒绝，不写入数据——由运行时保证，不依赖模型行为。

明确不采用转义规则：它要求写入方（模型）主动转义，而现有 API 模型无法被
强制，因此不作为协议依赖。编排层自行写入的内容可自行规避格式冲突，
属调用方约定而非协议约束。

### 2.7 示例

```python
# 生成前的声明：ref 列出直接依赖
agent_text = "<ref=4cd5f05386b7b6ab> 请核实这笔订单并给出退款金额"
# 解析结果（确定性提取）：
#   refs    → ["4cd5f05386b7b6ab"]
#   requires → []

# 生成中途的缺页请求
agent_text2 = "……金额确认了，但还需要换货政策。<require=9a3f6c1f...> 继续……"
#   requires → ["9a3f6c1f..."]

# 非法引用（幻觉或错误）
agent_text3 = "<ref=ffff0000ffff0000> 引用不存在的节点"
# 运行时校验 → 拒绝（报错），不写入任何数据
```

## 3. 目录与摘要

### 3.1 两级可见性

- **全文可见**：当前依赖集内的节点——模型实际阅读的内容；
- **目录可见**：可申请但未展开的节点，每条只给 id + 摘要——模型能看到存在与用途，看不到全文；
- 目录是展开上下文的组成部分，渲染在依赖集之后，按 id 排序（依赖集在前保持稳定，利于前缀缓存）。

### 3.2 可申请范围

- 每次展开由编排层指定可申请集合（候选集）；默认 = 最近注册的 N 个节点（N 可配，默认 1024，无硬预算上限）；
- 超长任务由编排层分而治之：按子任务分期或分组提供候选集；
- 软约定：候选集过大时编排层应裁剪，避免模型在目录中迷失。

### 3.3 摘要的定位

- 目录摘要的目标是"够判断相关性"，不是"准确概括全段"；
- 误判代价有界：多一次缺页请求或少引用一个节点，不构成灾难；
- 正确性不依赖摘要，由契约与兜底保证。

### 3.4 摘要的质量阶梯（按成本递增，逐级兜底）

1. **启发式提取（零成本）**：首行、结论指示词、任务关键词重合度选句——临时标签；
2. **显式 `<summary>`（按需）**：生产者自述，受益但不依赖其存在；
3. **读者摘要节点（读后写）**：交接场景主用，是正常协议操作
   （`register(content=摘要, refs=[被摘要节点])`），无格式税；
4. **LLM 摘要服务（懒加载）**：为进入目录但无其他摘要来源的节点生成
   决策辅助摘要；启发式提取始终兜底（服务不可用/未生成时）。

### 3.5 自愈目录

- 节点的目录描述取当前最好的一份：读者摘要节点 > 显式 `<summary>` > 启发式提取；
- 未读节点只有临时标签（质量低可接受）；被读节点描述随阅读次数变好。

### 3.6 展示层边界

- 节点 id 是机器键；人类可读展示（对话审查、节点超链接）由展示层基于
  "id → 全文/摘要"的解析能力实现，不进协议文字；
- 展示层不在协议卷范围，但协议保证其可实现。

### 3.7 相关机制与未来规划

目录 + require 与主流 agent 框架的"渐进式披露"（progressive disclosure）
是同一模式：提示词只放短描述，正文按需加载（Claude Skills、Vectara
skills 均如此）。据此：

- **目录条目的写法**：应为"决策辅助"——域 + 触发条件（什么情况下该用这个
  节点），而不只是内容首句摘要；描述质量直接决定 require 触发质量；
- **选择机制四类**：模型自主判断（固定小目录，基线默认）、编排层路由
  （Copilot orchestrator 式）、检索式（大规模时：稠密检索 + 重排，如
  SkillFlow）、训练式（学会"调用或跳过"，远期）；
- **规模分界**：固定小候选集用模型自选；千级以上才需要检索管线；
- **用户显式指定节点**（未来功能）：用户点名节点/文件 → 编排层直接并入
  依赖集或作为必选候选，与 Claude Code `skills` 白名单同款；
- **图关系作为候选信号**（未来）：节点依赖边可作"前置优先"排序依据
  （SkillGraph 思路）；
- **测量问题**：固定小目录 vs 检索的 token/质量权衡，留待测量层回答。

### 3.8 摘要的存储与生成（设计决策）

- **侧表存储，不进 meta**：摘要保存在节点之外的 `node_id → summary` 映射。
  `meta` 参与内容寻址（同内容必同 id），LLM 生成摘要的非确定性若写入
  meta 会破坏该不变量；侧表让摘要成为节点的外部属性，可随时替换、不影响 id；
- **懒生成 + 缓存**：节点注册时不生成摘要，第一次进入某次目录时才生成，
  之后缓存——避免 1024 级候选集的全量预生成成本；
- **小 LLM 摘要服务是可选加速器，不是协议**：摘要生成是一次性 complete，
  任务之间无 KV 复用，不依赖主引擎缓存，可用廉价小模型独立部署，不影响
  主链路；按"决策辅助"格式写（域 + 何时使用），而非首句压缩；
- **消费侧有 KV 复用**：目录按 id 稳定排序，同一目录反复进入上下文时可命中
  读者模型的前缀缓存——"生成无复用、消费有复用"，两者不矛盾；
- **嵌入向量 = 检索/排序信号，不是概述**：LLM 是文字原生模型，向量无法直接
  放入上下文（除非模型经训练消费该类 token）。向量的正确用途是编排层的
  大规模候选预筛/排序（稠密检索）、去重与聚类；API embedding 只提供池化向量
  （且来自独立 embedding 模型），拿不到对话模型的逐 token 激活，后者属本地
  权重专属能力、超出协议卷范围；
- **分层结论**：协议层维持"目录 = 文字摘要"；小 LLM 服务是可选增强；向量
  检索是候选集上千之后的编排层能力。
- **测量指标**：Session 计数展开次数、目录字符数（token 开销近似）、缺页
  请求次数、require 拒绝数（接地失败），用于校准 catalog_size 与判断是否
  需要升级到检索层。

## 4. 展开与会话

### 4.1 范围

纯文字层：**任何 API 模型都能使用**，不依赖任何推理引擎的内部实现。
协议层只负责"文字的组织与解析"；模型推理由外部引擎（黑盒）完成。

### 4.2 装配点：Session

会话（Session）是整套协议的使用入口，一条典型流程：

1. 注册根节点（无依赖）；
2. 展开某个节点的依赖集 → 得到模型将看到的上下文文字；
3. 把文字发给模型 → 模型生成回复；
4. 解析回复中的标签、校验、注册为新节点；
5. 下一个 Agent 展开它需要的依赖集（依赖增长、依赖集复用）。

核心操作：

- `expand(refs)`：展开依赖集，返回渲染文字；
- `register(content, refs)`：把生成好的正文登记为不可变节点；
- `require(id)`：缺页请求扩展（重新展开）；
- `read(id)`：取单个节点的全文；
- `full_context()`：全量兜底（忽略依赖图，把全部节点渲染出来）。

### 4.3 依赖集与展开

- 依赖集 = 从目标节点出发、沿直接依赖边能到达的全部节点（含它自己，即直接依赖 + 全部间接依赖）；
- 渲染顺序：规范拓扑序——依赖永远在依赖者之前，同层按 id 排序；
- 稳定序列化：同一节点在包含它的任何依赖集中字节完全一致；
- 因此"祖先恒居前缀"：两次展开若共享祖先，文字开头必然相同，
  对引擎自带的前缀缓存友好（这是设计红利，不是对引擎的依赖）。
- **内容保真**：节点内容按模型输出原样保存，不增删换行；块与块之间的分隔符
  是渲染层的显式规则（默认 "\n\n"），只作用于渲染文字，不触碰节点内容。

### 4.4 位置与引用

渲染结果中每个节点获得一个位置（序号）；上下文内按位置解析引用，
保证依赖集变化时引用仍然正确。

### 4.5 缺页请求与兜底

- `require` 的 id 必须来自当前目录（见第 3 章）；触发依赖集扩展与重新展开，
  缺页请求次数被记录（成本可见）；
- 校验失败（引用不存在/违反 grounding）→ 拒绝 + 兜底路径；
- 依赖集过大防御：展开支持深度上限，超限节点以占位符表示。

### 4.6 与引擎的关系

- 协议层与引擎之间只有一层薄适配器：协议层出文字、收文字；
- 引擎（API 或本地服务）是黑盒，通过接口调用即可；
- 引擎自带的前缀缓存是"可选项"：协议层的稳定渲染使其命中率最大化，
  但没有引擎缓存时协议层依然正确工作。

### 4.7 示例

```python
session = Session()

# 1) 注册根节点
brief = session.register(
    content="客户要求：退款订单 #X（$120），并换货为型号 A。",
    refs=[],
)

# 2) 展开依赖集 → 模型看到的上下文
ctx = session.expand(refs=[brief.id])
# ctx.text：
#   <node=4cd5f05386b7b6ab>
#   客户要求：退款订单 #X（$120），并换货为型号 A。

# 3) 模型回复 → 注册新节点
reply = model.generate(ctx.text)              # "已核实订单：金额 $120，符合退款条件。"
node1 = session.register(content=reply, refs=[brief.id])

# 4) 下一个 Agent 展开 node1 的依赖集：brief 自动带入
ctx2 = session.expand(refs=[node1.id])
# ctx2.text：
#   <node=4cd5f05386b7b6ab>
#   客户要求：退款订单 #X（$120），并换货为型号 A。
#
#   <node=a1c1bfccdf180645>
#   已核实订单：金额 $120，符合退款条件。

# 5) 缺页请求：中途发现还需要其他节点
ctx3 = session.require("9a3f6c1f...")         # 依赖集扩展后重新展开
# session.page_faults → 1
```

## 5. 约束

### 5.1 设计约束（系统必须满足）

- **引擎无关**：不 import、不依赖任何推理引擎；纯 API 模型可用；
- **纯 Python 标准库**：协议层本身不引入第三方依赖；
- **内容寻址**：同内容必同 id，修改必产生新节点；
- **不可变**：节点生成后不可修改；
- **无环**：依赖只能指向已存在节点（构造性保证无环、无前向引用）；
- **契约先行**：非法输入被拒绝，而不是静默接受；
- **稳定渲染**：同一节点在包含它的任何依赖集中字节一致。

### 5.2 运行时不变量（永远成立，测试骨架）

每条不变量对应将来的至少一组测试：

1. 已注册节点的每个依赖都指向已注册节点；
2. 节点不能引用自身；
3. 相同输入必然产生相同 id；
4. 同一节点在包含它的任何依赖集中渲染字节一致；
5. 依赖图无环（由"依赖必须先存在"保证）；
6. Grounding 开启时，refs 属于当前依赖集、requires 属于当前目录。

### 5.3 契约失败时的行为

- 拒绝该操作，不写入任何数据；
- 提供兜底路径（全量上下文 / 重试）；
- 失败可计数、可观测（如缺页请求次数）。

### 5.4 明确不在本卷范围

- 引擎内部优化（如按节点 id 管理 KV 缓存）——后续单独成章；
- 模型训练线（如让模型学会自主生成标签）——远期，由测量数据驱动；
- 非 API 模型（本地权重）专属的能力——不属于"纯 API 模型可用"范围。

```python
# 违反不变量 1：引用未注册节点

# 违反不变量 6（grounding 开启时）：引用不在当前上下文中的节点
session.expand(refs=[brief.id])
session.register(content="y", refs=["9a3f6c1f..."], grounded=True)
```
